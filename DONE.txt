Связанная сущность: участник клуба

1. НАЗНАЧЕНИЕ ПРОЕКТА
======================

Sport Club - консольная информационная система спортивного клуба.
Пользователь работает с участниками клуба и записями на тренировки через
интерактивное меню. Основные данные хранятся в PostgreSQL.

Архитектура приложения:

Console UI -> Service -> Repository / JDBC -> PostgreSQL

Роли слоев:

- Console UI принимает команды и данные пользователя, показывает меню и результат.
- Service содержит бизнес-правила, поиск, фильтрацию, сортировку и статистику.
- Repository выполняет SQL-запросы и преобразует строки ResultSet в объекты Java.
- Database хранит данные, связи и ограничения целостности.
- Util содержит подключение к PostgreSQL и экспорт в Excel.
- Exception содержит собственные исключения приложения.

Проект реализован на Java 17, собирается Maven и запускается локально или через
Docker Compose.

3. НАЗНАЧЕНИЕ КАЖДОГО ФАЙЛА
============================

Корневые файлы
--------------

pom.xml
Maven-конфигурация. Указывает Java 17, PostgreSQL JDBC-драйвер, Apache POI для
создания XLSX и exec-maven-plugin для запуска ru.sportclub.Main.

README.md
Краткая инструкция по локальному и Docker-запуску, архитектура, переменные
окружения и список бизнес-правил.

PROJECT_EXPLANATION.txt
Расширенное описание проекта и чек-лист соответствия требованиям КР1.

DONE.txt
Итоговый технический паспорт проекта: структура, назначение файлов, связи,
сценарии работы, правила, база данных, выполненные требования и запуск.

Dockerfile
Многоступенчатая сборка. Первый этап собирает проект Maven, второй запускает
скомпилированные классы и зависимости в Java 17 JRE-образе.

docker-compose.yml
Описывает два сервиса: PostgreSQL `postgres` и консольное приложение `app`.
Приложение подключается к БД внутри Docker-сети по адресу `postgres:5432`.
PostgreSQL доступен с компьютера по `localhost:5433`. Включены healthcheck,
stdin и tty для интерактивного запуска приложения, а volume сохраняет данные.

run.ps1
Вспомогательный PowerShell-скрипт запуска Java-приложения через Maven.

database/schema.sql
Создает таблицы `members` и `training_registrations`, ограничения, индекс,
пять тестовых участников и десять тестовых записей.

database/setup-local.ps1
Создает локальную базу `sportclub` и применяет schema.sql для PostgreSQL,
установленного как Windows-служба.

docs/ER-diagram.md
ER-диаграмма таблиц и внешней связи между участниками и записями.

Точка входа и интерфейс
-----------------------

src/main/java/ru/sportclub/Main.java
Точка входа программы. Создает DatabaseManager, репозитории, сервисы и
ConsoleApplication, затем запускает метод run(). Бизнес-логика в Main не хранится.

src/main/java/ru/sportclub/ui/ConsoleApplication.java
Главный консольный интерфейс. Содержит главное меню и подменю участников,
записей, поиска, фильтрации/сортировки, статистики и экспорта.

Класс читает ввод через Scanner, вызывает сервисы и выводит объекты. Меню
зациклено, поэтому после операции приложение не завершается. Ошибки ловятся на
уровне UI и выводятся пользователю без аварийного завершения программы.

Модели предметной области
-------------------------

src/main/java/ru/sportclub/model/Member.java
Модель участника: id, ФИО, телефон, email, тип абонемента и активность.
Поля private, есть конструкторы, методы доступа и toString().
Вложенный enum MembershipType содержит BASIC, PREMIUM и ANNUAL.

src/main/java/ru/sportclub/model/TrainingRegistration.java
Модель записи на тренировку: id, memberId, имя участника, название тренировки,
тренер, дата, время, длительность, статус, категория и дата создания.
Вложенный enum RegistrationStatus содержит PLANNED, CONFIRMED, COMPLETED и
CANCELLED.

Репозитории
-----------

src/main/java/ru/sportclub/repository/CrudRepository.java
Обобщенный интерфейс CRUD: save, findAll, findById, update и deleteById.
Через него MemberService работает с репозиторием по абстракции, что показывает
интерфейс и полиморфизм.

src/main/java/ru/sportclub/repository/MemberRepository.java
JDBC-реализация CRUD для таблицы members. Использует Connection,
PreparedStatement, ResultSet и try-with-resources. Также ищет участника по email.

src/main/java/ru/sportclub/repository/TrainingRegistrationRepository.java
JDBC-реализация CRUD для training_registrations. При чтении соединяет записи с
members через JOIN, преобразует ResultSet в TrainingRegistration и проверяет,
занят ли участником конкретный временной слот.

Сервисы
-------

src/main/java/ru/sportclub/service/MemberService.java
Сервис участников. Проверяет обязательные поля, email и наличие записи перед
изменением или удалением. Реализует создание, просмотр, поиск по ID, изменение
и удаление участников.

src/main/java/ru/sportclub/service/TrainingRegistrationService.java
Главный сервис предметной области. Реализует CRUD записей, поиск по названию
тренировки и тренеру, фильтры по статусу и категории, сортировку по дате/времени
и длительности, а также группировку статистики по статусам.

Здесь находятся бизнес-проверки: существование и активность участника,
обязательность названия и тренера, допустимая дата, длительность от 30 до 240
минут, отсутствие конфликта времени, допустимые переходы статусов и запрет
удаления или изменения завершенных записей.

Исключения
----------

src/main/java/ru/sportclub/exception/BusinessException.java
Сигнализирует о нарушении бизнес-правила или некорректном пользовательском вводе.

src/main/java/ru/sportclub/exception/EntityNotFoundException.java
Используется, когда участник или запись с указанным ID отсутствует.

src/main/java/ru/sportclub/exception/DataAccessException.java
Оборачивает ошибки JDBC, PostgreSQL и SQL-запросов в исключение приложения.

Утилиты
-------

src/main/java/ru/sportclub/util/DatabaseManager.java
Читает SPORTCLUB_DB_URL, SPORTCLUB_DB_USER и SPORTCLUB_DB_PASSWORD и создает
JDBC Connection через DriverManager. Для локального запуска есть значения по
умолчанию.

src/main/java/ru/sportclub/util/ExcelExporter.java
Создает exports/sport-club-data.xlsx через Apache POI. В файле два листа:
"Участники" и "Записи на тренировки".

4. ЛОГИКА РАБОТЫ ПРОГРАММЫ
===========================

1. Main создает DatabaseManager.
2. Main передает DatabaseManager в MemberRepository и
   TrainingRegistrationRepository.
3. Main создает MemberService и TrainingRegistrationService.
4. Main передает сервисы в ConsoleApplication.
5. ConsoleApplication.run() показывает главное меню и читает команду.
6. UI передает операцию соответствующему Service.
7. Service проверяет бизнес-правила и вызывает Repository.
8. Repository открывает Connection, выполняет параметризованный SQL через
   PreparedStatement, читает ResultSet и возвращает объект или список объектов.
9. Результат возвращается через Service в UI и выводится пользователю.
10. Ошибки преобразуются в собственные исключения и показываются в меню.

Связь объектов при записи на тренировку:

ConsoleApplication
    -> TrainingRegistrationService
        -> TrainingRegistrationRepository
            -> training_registrations
                -> members через member_id

При создании записи сервис дополнительно обращается к MemberRepository, чтобы
убедиться, что участник существует и активен.

5. БАЗА ДАННЫХ И СВЯЗИ
=======================

Таблица members:

- id - PRIMARY KEY;
- full_name - обязательное ФИО;
- phone - обязательный уникальный телефон;
- email - обязательный уникальный email;
- membership_type - BASIC, PREMIUM или ANNUAL;
- active - признак активности участника.

Таблица training_registrations:

- id - PRIMARY KEY;
- member_id - обязательный FOREIGN KEY на members.id;
- training_name - название тренировки;
- trainer_name - тренер;
- training_date и start_time - дата и время;
- duration_minutes - от 30 до 240 минут;
- status - PLANNED, CONFIRMED, COMPLETED или CANCELLED;
- category - категория тренировки;
- created_at - время создания записи.

Связь:

training_registrations.member_id -> members.id

В базе также есть составной уникальный индекс на member_id, training_date и
start_time. Он запрещает записать одного участника дважды на один временной слот.
Внешний ключ использует ON DELETE RESTRICT, поэтому участника с записями нельзя
удалить без предварительного удаления связанных записей.

6. БИЗНЕС-ПРАВИЛА
==================

1. Запись создается только для существующего участника.
2. Неактивного участника нельзя записать на тренировку.
3. ФИО, телефон, email, название тренировки и тренер обязательны.
4. Email участника должен содержать символ @.
5. Дата тренировки не может быть в прошлом.
6. Длительность тренировки должна быть от 30 до 240 минут.
7. Нельзя создать две записи одного участника на одну дату и время.
8. Новую запись нельзя сразу создать со статусом COMPLETED.
9. Завершить можно только запись со статусом CONFIRMED.
10. Завершенную или отмененную запись нельзя редактировать.
11. Завершенную запись нельзя удалить.
12. Ввод ID и числовых значений проверяется до обращения к базе.

0. Выход

CRUD участников:

- добавить участника;
- вывести всех участников;
- найти участника по ID;
- изменить активность;
- удалить участника.

- создать запись;
- вывести все записи;
- найти запись по ID;
- изменить запись;
- удалить запись.

Поиск выполняется двумя способами: по названию тренировки и по тренеру.
Фильтрация выполняется по статусу и категории.
Сортировка выполняется по дате и времени, а также по длительности по убыванию.

Статистика выводит минимум пять показателей: число участников, число активных
участников, общее число записей и количество записей по четырем статусам.

10. ЗАПУСК ПРОЕКТА ЧЕРЕЗ DOCKER
===============================

В PowerShell из C:\sportclub:

    cd C:\sportclub
    docker compose build app
    docker compose up -d postgres
    docker compose run --rm app

Эта последовательность запускает PostgreSQL в фоне и Java-приложение в
интерактивном режиме, поэтому команды меню можно вводить с клавиатуры.

Если образ приложения не менялся, достаточно:

    cd C:\sportclub
    docker compose up -d postgres
    docker compose run --rm app

Для полной пересборки базы с тестовыми данными:

    docker compose down -v
    docker compose up -d postgres
    docker compose run --rm app

Ключ -v удаляет volume базы, поэтому использовать его нужно только при
намеренной очистке данных.

Для остановки контейнеров:

    docker compose down

11. ЛОКАЛЬНЫЙ ЗАПУСК БЕЗ DOCKER
